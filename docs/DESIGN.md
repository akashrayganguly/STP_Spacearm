# DESIGN — Neural kinematics + constrained RL for a 7-DOF free-floating space manipulator

Status: v1.0 (frozen for implementation). Every number lives in `configs/default.yaml`.
If you change a decision, update this file, the config and the affected tests together.

---

## 1. Scope

| Level | Deliverable | Runs |
|---|---|---|
| **1** | Kinematics-aware model: given current joint angles and a target point, return a **collision-free joint trajectory** and **goal joint angles** that never hit the spacecraft body (bus, solar panels, payload) or the arm itself. | offline-trained, ~0.1 s per plan |
| **2** | **Lightweight DRL policy** that re-routes the arm **in real time** when a surprise obstacle appears or joint hardware misbehaves (encoder bias, weak actuators, slips), on a **free-floating** spacecraft. | 10 Hz closed loop, < 1 ms per step |

Scope decisions (critical):
* **"Multi-axis" in the brief = multi-joint.** The core is **one 7-DOF arm**. A second arm ("codependent arms") is the **stretch Phase 8**; the RL design is already multi-agent-ready (shared actor + centralised critics).
* **Dataset = generated by us in PyBullet.** There is no ready-made "OpenRAVE/PyBullet space robot dataset". OpenRAVE has no maintained Windows build for modern Python, so we use **PyBullet only**.
* **Quick but sound:** no RRT, no meshes, no GPU required. Every module has a unit test; every model has an acceptance target.

## 2. Architecture

```
LEVEL 1  (plan once, ~0.1 s)
 q_start, target ─► TrajNet ─► Bezier control points ─► refine (30 Adam steps on the loss)
                     │            (joint limits by          │
                     │             construction)            ▼
                     │                           IK polish (damped least squares on exact FK)
                     │                                       │
                     │   loss = reach(FK) + clearance(DistanceNet) + smoothness
                     ▼                                       ▼
               DistanceNet (q -> clearance)         PyBullet verification ─► retry (100 steps) if needed
                                                             │
                                                             ▼
                                              joint path + goal joint angles

LEVEL 2  (every 100 ms, < 1 ms compute)
 sensors ─► features (FK, DistanceNet clearance+gradient, obstacle clearance+gradient)
               │
               ├─► actor MLP 56-64-64-7 (~8k params) ── x0.5, fades near target ─┐
               └─► reflex prior (DLS reach + null-space + repulsion) ────────────┴─► + ─► safety shield ─► joint velocities
```

## 3. Key decisions and why

| # | Decision | Why | Rejected alternative |
|---|---|---|---|
| D1 | Own URDF generated from config: bus + panels + payload boxes, **capsule** arm links with KUKA-iiwa-like S-R-S sizes | Exact known kinematics (FK unit-tested to 1e-5 m), fast exact distances, explicit mass properties, no mesh paths on Windows | KUKA mesh URDF (unknown exact geometry, slow mesh distances) |
| D2 | **Level 1 works in the spacecraft body frame** | Arm-vs-own-spacecraft collision depends **only on joint angles**, not on base motion, so Level 1 is exact without dynamics | Planning in the inertial frame (needs dynamics) |
| D3 | **Free-floating effects are handled closed-loop in Level 2** | Validation: Level-1 plans played open-loop on the floating spacecraft miss an inertial target by **~13 cm median (34 cm max)** because the base rotates ~6° in reaction. Closing the loop on the vision-measured TCP->target vector removes this | Generalised-Jacobian open-loop planning (more maths, still open-loop) |
| D4 | **Geometric collision checking, no contact physics**, "ghost" obstacles | Contact forces would push the arm/spacecraft and *hide* collisions after a physics step; episodes end at first penetration anyway | PyBullet contact physics |
| D5 | **Allowed-collision matrix** (`robot.acm_skip`) | Some link pairs are always ~2–8 cm apart but can never collide (e.g. link5–link7 across the short wrist). Including them caps the clearance and makes any margin infeasible. A test proves the skipped pairs never collide | Min over all pairs |
| D6 | **DistanceNet**: SiLU MLP on `[sin q, cos q]` -> `(d_body, d_self)`, smooth-min clearance | FK is built from sin/cos, so these features are natural and periodic; SiLU gives smooth gradients (needed by optimisation and the shield); smooth-min is conservative (never over-estimates) | ReLU (piecewise-constant gradients); binary collision classifier (no margin, no gradient) |
| D7 | **Self-supervised trajectory learning** (train on outcomes, not labels) | 7-DOF IK is redundant: infinitely many correct answers. Regressing to labelled answers averages them into wrong ones. Outcome losses (FK reach error, clearance, smoothness) avoid this and need no planner-made labels | Supervised regression on RRT paths |
| D8 | **Degree-7 Bezier** with control points squashed into joint limits, `P0=P1=start`, `P6=P7=goal` | Whole path inside limits (convex-hull property), rest-to-rest motion, 35 outputs instead of T x 7 | Raw waypoints |
| D9 | **Learned proposal -> exact refinement -> verification** | The network is fast but approximate. Refinement fixes residual collisions, DLS polish gives mm accuracy, PyBullet verification makes every reported success real | Trusting the raw network |
| D10 | **Residual RL on a classical reflex prior** (DLS reaching + null-space self-avoidance + obstacle repulsion) | Layered like real space-robot software: deterministic reflexes keep the arm off the spacecraft and off a surprise obstacle; the learned residual does what reflexes cannot: **re-route around** an obstacle instead of stalling in front of it (local minimum), compensate faults and base motion. Validation: pure RL had 0 % success after 130k steps; the residual starts at the prior's level and beat it after 0.3 M steps (S4 55 % vs 47.5 %). Prior alone at full difficulty: ~45 % success / ~3–8 % collisions with the repulsion reflex vs ~40 % / ~50 % without it | Pure RL from scratch; learning avoidance with no reflex (kept as ablation `prior.k_obs = 0`) |
| D11 | **PPO-Lagrangian** with a separate cost critic | The constraint weight lambda is *learned* by dual ascent on "mean episode cost − limit"; no hand-tuned penalty. Validation on the toy task: unconstrained PPO cost 7.0/episode, PPO-Lagrangian 0.84 (limit 1.0) at 100 % success | Fixed reward penalty |
| D12 | **Asymmetric actor-critic** | The actor sees only what the robot would know (biased encoders, noisy vision). The critics also see the truth (bias, true clearances). Better training, deployable actor | Symmetric |
| D13 | **Kinematics-aware observations**: joint-space gradients of self- and obstacle-clearance | Avoidance becomes a near-linear mapping ("move along the gradient when close") | Cartesian-only features |
| D14 | Critic observes `t/T`; any episode end cuts the bootstrap | Correct value targets at time-outs (Pardo et al., 2018) without carrying final observations | Ignoring time limits |
| D15 | **Safety shield** after the policy | Learned constraints are soft. The shield checks the command against FK + DistanceNet + analytic sphere–capsule distances with margins. Honest limit: not a formal proof, only as good as its models | Trusting the policy |
| D16 | **CPU training, tiny actor, NumPy/ONNX deployment** | Physics is CPU-bound; PPO with small MLPs is fastest on CPU. The deployed actor is 3 matrix multiplies (~10 µs in NumPy). GPU optional | Large nets, GPU-only |
| D17 | Single arm core, dual-arm stretch | Brief says "multi-axis manipulator"; code already supports an agent dimension | Starting with two arms |

## 4. World model (`robot_model.py`, `sim.py`, `kinematics.py`)

**Frames.** Body frame B = bus centre (= bus centre of mass): z up through the arm-mount face, y along the solar panels. With the base at identity (Level 1, data generation), world = body.

**Geometry (default config).**

| Part | Shape | Size (m) | Mass (kg) |
|---|---|---|---|
| Bus | box | 1.0 x 1.0 x 1.0 | 150 |
| Solar panels (2) | box | 0.8 x 1.6 x 0.02, centred y = ±1.35 | 10 each |
| Payload | box on top deck | 0.40 x 0.50 x 0.30 at (−0.20, 0, 0.65) | 20 |
| Pedestal | cylinder | r 0.07, h 0.10 at (0.30, 0, 0.50) | 4 |
| Arm links 1–7 | capsules along +z | lengths 0.24/0.20/0.20/0.20/0.20/0.14/0.12, radii 0.06…0.04 | 4/3/3/2.5/2.5/1.5/1.5 |
| TCP | point | 0.15 beyond joint 7 | 0.01 |

Joint axes z-y-z-y-z-y-z (shoulder 3, elbow 1, wrist 3). Limits ±170/120/170/120/170/120/175°. Max speed 0.5 rad/s (space arms are slow). Shoulder 0.34 m above the mount, reach ~1.1 m from the shoulder. Arm 18 kg vs spacecraft 194 kg, so the base reaction is clearly visible.

**Physics.** Zero gravity; **zero linear/angular/joint damping** (otherwise momentum leaks); velocity motors with 100 N·m limit; 240 Hz physics, 10 Hz control (24 substeps). Tests prove the system centre of mass stays fixed (< 2 mm) and the base rotates when the arm moves and stops when the arm stops.

**Collision.** Distances come from `getClosestPoints` over an explicit pair list:
arm links x spacecraft parts (30 pairs) and non-adjacent arm–arm pairs (10 pairs), after removing parent–child pairs and the ACM. `d_body` and `d_self` are signed minima (negative = penetration), clipped at 0.30 m. No contact forces (D4).

**FK in PyTorch.** Batched, differentiable: `forward(q) -> (R (...,8,3,3), t (...,8,3))` for link1..link7 + TCP, `tcp(q)`, analytic `jacobian(q)` (column i = z_i x (p_tcp − p_i)), `capsules(q)`.

**Pitfalls guarded by tests.**
* `getLinkState(...)[0]` is the **centre of mass**, `[4]` is the URDF link frame. FK compares with `[4]`.
* Every PyBullet call passes `physicsClientId` (one client per object; required for multiprocessing).
* Never hard-code PyBullet indices; build name -> index maps from `getJointInfo`.

## 5. Level 1

### 5.1 Dataset (`datagen.py`, `scripts/gen_data.py`)
* 200 000 configurations: 75 % uniform inside 98 % of each joint range + 25 % **boundary samples** (near-surface samples, |d| < 5 cm, perturbed with sigma 0.05 rad).
* Labels per sample: `q (7)`, `d_body`, `d_self` (signed, m), `tcp (3)` (body frame). float32 `.npz`.
* Separate 20 000-sample uniform test set (different seed). Generation takes ~1 minute (~0.15 ms per sample).
* Expected: ~12 % of uniform samples collide (mostly with the bus/payload); ~21 % of the full dataset after boundary sampling.

### 5.2 DistanceNet (`models/distance_net.py`, `scripts/train_distance_net.py`)
* `[sin q, cos q] (14) -> 256 -> 256 -> 256 -> 2`, SiLU. 136k parameters.
* Loss: Huber (beta 0.02) on targets clipped to [−0.05, 0.30], weight x10 where |d| < 5 cm.
* AdamW, lr 2e-3 cosine -> 0, batch 1024, 60 epochs (~1–2 min on CPU).
* `clearance(q) = −tau·logsumexp(−d/tau)`, tau = 1 cm: always <= the true minimum of the two heads.
* Report on the test set: MAE (all, and |d| < 10 cm), sign accuracy, **false-safe rate** (predicted > 3 cm while actually colliding). False-safe is the safety-critical number.

### 5.3 TrajNet (`models/traj_net.py`, `losses.py`, `scripts/train_traj_net.py`)
* Input `[sin q_start, cos q_start, target] (17) -> 512 x 3 SiLU -> 35` = pre-squash goal `u_goal (7)` + 4 interior control-point offsets `delta (4 x 7)`. Last layer zero-initialised.
* Control points: `P0 = P1 = q_start`, `P_k = squash(lerp(unsquash(q_start), u_goal, k/7) + delta_k)` for k = 2..5, `P6 = P7 = squash(u_goal)`, with `squash = mid + half·tanh`.
* Loss on T = 16 curve samples: `100·|FK(q_goal) − target|² + 1000·mean(relu(0.05 − clearance)²) + 0.1·sum|ΔQ|²`.
* Training queries: random pairs from the collision-free pool (dataset samples with clearance > 5 cm); target = FK of the second sample (always reachable). AdamW 3e-4 cosine, batch 256, 10 000 steps (~4 min on CPU).

### 5.4 Planner (`planner.py`)
`plan(q_start, target)`: network -> **refine** (30 Adam steps, lr 0.05, on the same loss) -> **polish** (10 damped-least-squares IK steps on the exact Jacobian, damping 0.01, clamped to limits) -> sample 100 points.
`plan_and_verify(...)`: exact PyBullet check (clearance > 0 at all 100 points, reach error < 2 cm, within limits); if it fails, re-plan once with 100 refine steps.

### 5.5 Level-1 evaluation (`scripts/eval_level1.py`)
* **Random set**: 200 queries. **Hard set**: 100 queries on which the classical baseline collides (~5 % of random queries, so sample until 100 are found).
* **Baseline**: PyBullet IK (null-space) + straight-line joint interpolation.
* Methods: baseline / network only / network + polish / full planner (refine + polish + verify-retry).
* Metrics: success, collision rate, median reach error, median plan time.
* **Free-floating check**: play 20 planned paths open-loop on the floating spacecraft and report the inertial miss and base rotation (motivates Level 2).

## 6. Level 2

### 6.1 Environment (`envs/space_reach_env.py`), gymnasium API
* **Reset**: random collision-free start (clearance > 5 cm) and target (TCP of another free configuration, >= 0.2 m away). The target is **fixed in the inertial frame**, so base drift matters.
* **Action**: `(1, 7)` in [−1, 1]. Residual mode: command = `clip(prior + 0.5·fade·action)` with `fade = min(1, distance_to_target / 10 cm)`, joint velocity = command x 0.5 rad/s. The residual has half authority and fades out near the target, so the prior alone does the final precise approach.
* **Observation** `{"actor": (1, 56), "critic": (90,)}`

| actor slice | content (all onboard-measurable) |
|---|---|
| 0:7 | measured joint angles, normalised to [−1, 1] (**includes encoder bias + noise**) |
| 7:14 | measured joint velocities / v_max |
| 14:17, 17 | TCP->target vector in body frame from vision (+noise), its length |
| 18:21 | gyro: base angular velocity in body frame / 0.1 |
| 21:24, 24, 25 | obstacle centre relative to TCP (vision), radius, active flag |
| 26, 27:34 | model-based obstacle clearance / 0.1 and its **joint-space gradient** (unit) |
| 34, 35:42 | DistanceNet self-clearance / 0.1 and its **joint-space gradient** (unit) |
| 42:49 | previous command |
| 49:56 | prior command |

Critic = actor features + 34 privileged values: true joint angles, encoder bias, actuator gains, base quaternion, base linear velocity, true self- and obstacle clearance, obstacle velocity, t/T.

* **Reward** `10·(d_prev − d) − 0.01·|a − a_prev|² − 0.005 + 5·success − 0.02·|a_policy|²` (progress term is potential-based, so it does not change the optimal policy; the last term keeps the residual small unless it pays off).
* **Cost** = 1 if the true minimum clearance (self, body or obstacle) < 2 cm.
* **Termination**: collision (clearance <= 0) or success (TCP within 2 cm and slower than 5 cm/s). **Truncation** at 200 steps (20 s).
* **Surprises** (scaled by difficulty d in [0, 1]):
  * obstacle (probability 0.8·d): sphere r 5–12 cm, appears at t ∈ [1, 5] s between TCP and target (±5 cm), half of them drift at up to 3 cm/s;
  * faults: encoder bias up to ±2°·d per joint, actuator gain in [1 − 0.3·d, 1], 30 %·d chance of a ±3° encoder slip mid-episode;
  * noise: encoder 0.1°·d, vision 5 mm·d, gyro 0.002 rad/s·d.
* **Curriculum**: d ramps linearly 0 -> 1 over the first 50 % of training.

### 6.2 Classical prior (`control.py`)
`qdot = J⁺·v + (I − J⁺J)·k_null·w_s·∇d_self + k_obs·w_o·∇d_obs`, with `v = clip_norm(1.0·(TCP->target), 0.15 m/s)`, `J⁺ = Jᵀ(JJᵀ + 0.05²I)⁻¹`, and weights `w` ramping from 0 to 1 as the clearance falls below 10 cm (self) / 15 cm (obstacle).
* The null-space term uses the 7th DOF to push away from the spacecraft **without moving the hand**.
* The repulsion term (`k_obs = 0.5 rad/s`) is a reflex: it keeps the arm off a surprise obstacle but stalls in front of it when the obstacle sits on the straight path. Getting around it is the policy's job.
* Validation (prior alone, 40 episodes): nominal ~80 % success; full difficulty ~45 % success with ~3–8 % collisions (without the reflex: ~40 % success, ~50 % collisions).

### 6.3 PPO-Lagrangian (`rl/ppo_lag.py`, `rl/vec_env.py`)
* Actor `56 -> 64 -> 64 -> 7` tanh mean, state-independent log-std (init −1.6, sigma ~0.2: small exploration around the prior). Reward and cost critics `90 -> 256 -> 256 -> 1`. Orthogonal init. Running mean/std observation normalisation (clip ±10).
* Per update: 8 envs x 256 steps; GAE (gamma 0.99, lambda 0.95) separately for reward and cost; **lambda <- clip(lambda + 0.05·(mean episode cost − 1.0), 0, 10)**; advantage `(A_r − lambda·A_c)/(1 + lambda)`, standardised per minibatch; 10 epochs x 8 minibatches, clip 0.2, early stop at KL > 0.02; grad-norm 0.5.
* **Keeping the residual from hurting the prior.** In validation, a full-authority residual made early policies *worse* than the prior (S4 success 22–30 % vs 47.5 %): it disturbed the final 2 cm approach. Four safeguards fixed it: **half-authority residual that fades out within 10 cm of the target**; critics train alone for the first 10 updates; actor learning rate 1e-4 (critics 3e-4), both decayed linearly; residual-size penalty in the reward. With them, 0.3 M steps already beat the prior (S4 success 55 % vs 47.5 %). Finally, **best-checkpoint selection**: every 25 updates the training script evaluates the deterministic policy on 20 fixed-seed episodes at full difficulty and keeps `models/ppo_lag.pt` only if success improves without more collisions. If the policy never beats the prior, ship prior + shield and say so.
* Budget 3 M steps. Expect roughly 1.5–3k steps/s on an 8-core workstation (20–40 min) and 300–440 steps/s on 2 cores (2–3 h).
* Parameter-shared actor over an agent dimension `(n_envs, n_agents, ·)` + centralised critics = **MAPPO-ready** for Phase 8.
* Always run the slow toy test first: if PPO-Lagrangian cannot solve `PointHazardEnv`, do not start the arm run.

### 6.4 Safety shield (`safety/shield.py`)
Predict `q' = q + s·a·v_max·0.2 s` (2 control steps) for s in {1, 0.5, 0.25}; accept the largest s with `h(q') >= 0`, where `h = min(DistanceNet clearance − 5 cm, obstacle clearance − 5 cm)` (obstacle clearance = analytic sphere–capsule distance on exact FK). If none is safe, command `0.5·∇h/|∇h|∞` (escape), or zero if escaping does not help.
* The shield only knows the **measured** joint angles, which carry up to ~5° of encoder bias + slip. The 5 cm self-margin covers that plus the DistanceNet error (validation: a 3 cm margin let 5 % of S4 episodes graze the bus; 5 cm: 2.5 %).

### 6.5 Deployment (`export.py`)
Actor with observation normalisation baked in -> **NumPy `.npz`** (3 matmuls, ~10 µs) and **ONNX** (opset 17). Report parameter count, p50/p99 latency of actor, prior, shield and full step on one CPU thread.

### 6.6 Level-2 evaluation (`scripts/eval_level2.py`)
Four scenarios x 100 fixed-seed episodes: **S1** nominal (d = 0), **S2** obstacles only, **S3** faults + noise only, **S4** everything (d = 1).
Methods: prior only | prior + shield | RL residual | RL residual + shield | (ablations) reflex off (`k_obs = 0`), pure RL.
Metrics: success, collision rate, mean episode cost, time to reach, base rotation, compute per step.

## 9. Risks and fallbacks

| Risk | Sign | Fallback |
|---|---|---|
| PyBullet fails to install on Windows | pip tries to compile C++ | Install from **conda-forge** (environment.yml does this) |
| Windows multiprocessing errors | `RuntimeError ... freeze_support` / hangs | `if __name__ == "__main__":` guard; picklable env factory; `--vec sync` to debug |
| CPU oversubscription | everything slow while training | `torch.set_num_threads(1)` in workers (env does it); `OMP_NUM_THREADS=1` |
| DistanceNet weak near the surface | false-safe > 0.5 % | more boundary samples (0.4), more epochs, keep the shield margin |
| Level-1 hard-set success low | < 90 % | refine 100 steps, train 20k steps, raise `w_coll` |
| RL residual makes things worse early | eval success below the prior's | expected in the first few hundred k steps; warm-up, small actor lr and residual penalty limit it; best-checkpoint selection keeps the best policy |
| RL not improving on the prior | eval success flat after 3 M steps | check the toy test; 5 M steps; longer curriculum (0.7); `lambda_lr` 0.02 if lambda saturates at 10; success bonus 10 |
| RL target not met in time | below targets | ship prior + shield (safe baseline), report RL honestly as an ablation; the shield alone already cuts collisions ~10x |
| ONNX export error | exporter complains | `pip install onnxscript`, or ship the NumPy export (enough for the latency claim) |

## 10. Stretch: two codependent arms (Phase 8)
* Second arm mounted e.g. at (0.30, ±0.30, 0.50) or on the opposite face; `env.n_arms = 2`.
* Per-arm actor features + the other arm's elbow/wrist/TCP positions (9) + agent one-hot (2); **shared actor** (parameter sharing), **centralised critics** see both arms and the base. Team reward; cost also counts arm–arm clearance (capsule–capsule distance).
* The arms are coupled through the floating base (momentum): one arm's motion moves the other arm's hand. The centralised critics see the base state and both arms during training; each arm runs the shared actor on its own observations at execution (centralised training, decentralised execution = MAPPO-Lagrangian).
* The DistanceNet must be retrained for the new geometry; arm–arm distance is analytic (capsules).
